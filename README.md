# Сільпо Pack Agent 🧾

Агент, який збирає **паки** — іменовані набори справжніх товарів «Сільпо» — з
твоїх реальних чеків, купонів і акцій, а тоді кладе їх у **справжній кошик**
твого акаунта. Проєкт для хакатону **«Сільпо» AI Factory**.

Все, що бачиш нижче, працює на офіційному MCP `https://mcp.silpo.ua/mcp`.
Моків у репозиторії немає.

## Ідея в одному абзаці

Ми не робимо другого асистента. Машрум Генадійович уже є в застосунку «Сільпо»
й уже має 40 MCP-tools. Ми даємо йому **три навички, яких у нього не було**:

| Навичка | Що означає | Ключові сценарії |
|---|---|---|
| **Памʼять** | знає, хто перед ним, що йому можна і що він любить — алергії, родина, компанія, трекери, ваги смаку | «Вечеря на всю сімʼю», «Компанія на один вечір» |
| **Турбота** | помічає поріг доставки, вагу кошика, купон і промо — **до** каси, а не на ній | «Топати чи замовити», «Пораховано до кошика» |
| **Прогрес** | кожен чек щось означає: портрет із покупок і рівень, що росте з кожним із них | «Куди йдуть гроші», «Грибниця» |

Головний принцип: **жодне число не вигадане**. Кожна цифра на екрані виведена
з відповіді MCP, і панель «Що відбувається» показує цей ланцюг викликів наживо.

## Три нові концепти персональних даних

MCP «Сільпо» віддає склад родини, дієти з «Простору вподобань», чеки й
«Обране». Але не віддає трьох речей, без яких персоналізація не працює.
Кожен концепт — це дані **і** tools до них; дані живуть у нас
(`.mcp/proposed.json`), бо в API для них немає місця.

### 1. Алергії та вподобання кожного в родині

`get_my_family` дає лише склад родини; смаки й алергії кожного члена лишаються
в застосунку. Ми додаємо їх поіменно: Арсен — горіхи, Оля — арахіс, Назар —
піца й кола, кіт Мурчик — корм.

- `silpo_get_family_preferences⁺` — склад родини з `get_my_family` **плюс**
  likes / avoid / allergies кожного. Кешується на 5 хв (сценарій читає родину
  раз, а не двічі).
- `silpo_set_member_preferences⁺(member_id, likes, avoid, allergies, name)` —
  правка з картки «Хто вечеряє → Змінити» або з профілю. `name` потрібен, бо
  API віддає другого дорослого без імені (`name: null`).

Алергія — жорстке виключення: перевірка йде по кореню слова, «мак» не блокує
«зі смаком», але блокує «рулет з маком». Складу товару MCP не віддає, тож це
чесно названо перевіркою за назвою.

### 2. Трекери й комора

Фітнес, сон, настрій, менструальний цикл — і розумний холодильник. Джерела
демонстраційні (перемикач засіває правдоподібні значення), але **поля —
справжній контракт**, який ми просимо в цих застосунків.

- `silpo_list_connectors⁺` / `silpo_connect_source⁺(source, on)` — Samsung
  Family Hub, Flo, Google Fit, Daylio, Google Календар.
- `silpo_wellbeing_sync⁺(source, mood, sleep_hours, workout, cycle_phase)` /
  `silpo_wellbeing_state⁺` — самопочуття зараз: «силове тренування, сон 5,5 год».
- `silpo_pantry_sync⁺(items, source)` / `silpo_pantry_state⁺` /
  `silpo_pantry_missing⁺` — що лежить удома, з термінами; агент не купує те,
  що є, і помічає прострочене.

Профіль → **Трекери** (джерела й поля) і **Що є удома** (полиця + техніка на
кухні: рецепти, що вимагають відсутнього, не пропонуються).

### 3. Ваги смаку

Найголовніше. «Департамент дивинок» у «Сільпо» знає лише про свайп вправо, а
лівий ігнорує — бо в API немає місця для відмови. Ми записуємо обидва:

| Подія | Товар | Його полиця |
|---|---|---|
| свайп вправо | +2 | +2 |
| свайп уліво | −2 | −2 |
| покупка з чека | + | + |
| заміна в паку | − | — |

Так виходить **вага**: звичне вище, свайпнуте вліво — нижче. Відʼємна вага —
мʼяка нелюбов, не алергія: впливає на порядок, але нікого не виключає.

- `silpo_get_taste_weights⁺(limit)` — знімок: топ товарів і полиць з вагами
  (зараз ~130 товарів із 32 чеків і свайпів).
- `silpo_record_swipe⁺(product_id, liked, name)` — свайп; вправо ще й іде в
  «Обране» акаунта через офіційний `add_or_update_favorite_products`.
- `silpo_get_swipe_deck⁺` — колода «Департаменту дивинок»: акційне з улюблених
  полиць плюс одна полиця «на виріст», без уже купленого й уже свайпнутого.
- `silpo_bump_taste_weight⁺`, `silpo_rebuild_taste_weights⁺` — службові:
  зрушити вагу подією; перерахувати все з чеків заново.

Ваги живуть у `.mcp/weights.json` і рухаються **лише** особистими подіями —
пікнік із компанією їх не збиває (див. нижче).

## Компанія на один вечір

Разова група під подію — пікнік, шашлики, день народження. Це **не** «Сімейний
доступ» «Сільпо»: там сталий звʼязок акаунтів заради спільних бонусів, тут —
один вечір. Тому компанія — окрема сутність: зібрав, покликав, розрахувались,
прибрав. У MCP такого немає ніде; учасники й пропозиції зберігаються в нас.

Три правила:

1. **Уподобання кожного.** Алергія будь-кого блокує товар для **всього**
   кошика — окремої тарілки на пікніку не буває. Дієти (без лактози,
   вегетаріанська) показуються, але кошик не блокують.
2. **Пропозиція кожного.** Будь-хто докидає своє в список і пропонує заміни —
   кошик однієї людини завжди когось забуває. Кожна позиція підписана, хто її
   запропонував.
3. **Розділити оплату.** Рівна частка мінус сплачене. Частку можна закріпити
   («Тарас — 120, він бере лише пиво») або гість пропонує її сам зі свого
   телефона, а організатор приймає. Перекази між своїми зводяться до мінімуму;
   грошей ми не рухаємо — суми готові до передачі в банківський «розділити
   чек», як у mono.

І головне — компанія **не збиває особисті ваги смаку**: те, що ви їли на
пікніку, не стає вашим смаком.

### Як це виглядає

1. У чаті: «Збираємось компанією на пікнік у суботу» → асистент **пропонує**
   створити «Пікнік» (нічого не створює без натискання).
2. «Створити компанію» → картка з **QR і посиланням** `/join?crew=…`. Кожен
   відкриває його зі свого телефона й каже про себе сам: імʼя, алергії, дієта,
   що взяти — і може запропонувати свою частку чека.
3. «Запропонуй в компанію з імʼям Пікнік закупку на пікнік» → кошик із
   пропозицій усіх, «Виключено для всіх: горіхи (Марина), мед (Ірина)».
4. Під кошиком — «+ пропозиція» (кошик перезбирається) і «Розділити чек».
5. Профіль → **Компанії** — та сама компанія як обʼєкт із редагуванням.

Компанії разові й на це розраховані: **кожен перезапуск сервера і кожен
«чистий дубль» стирають їх**, і чат знову починає з пропозиції.

## Сценарії

Кожен сценарій — це одна фраза гостя і ланцюг tools під нею. Усі ланцюги
зареєстровані в `silpo_agent_mcp/flows.py` і показані в UI: карткою сценарію
ліворуч і стрічкою «Що відбувається» праворуч. Нижче — ті, що в пітчі.

### «Збери вечерю, щоб усім підійшло» — Памʼять у дії

Одна фраза — чотири джерела одночасно. Результат — не список продуктів, а
**страва** й кошик під неї.

```
get_my_family → get_family_preferences⁺   хто вечеряє й що йому можна
wellbeing_state⁺                           сон, тренування → підказка для страви
get_taste_weights⁺                         що любить, пораховано з чеків
pantry_state⁺                              що вже вдома — не купуємо
find_recipes⁺                              страва під усіх; відхилені — з іменем
find_products_batch                        товари під страву — з каталогу
get_my_coupons · get_my_promos · get_coupon_details · select_promos⁺
                                           знижки під цей кошик — самі
add_or_update_cart_products → get_shopping_cart_by_id
                                           у справжній кошик — і перечитати
```

Метод: `family_pack(theme, max_uah, novelty, prefer_promo, avoid, equipment, dish)`.
Страва обирається зі всіх даних одразу: лайки ×2, білок після тренування +1,5,
ваги смаку, кількість порцій; рецепти з алергеном будь-кого відхиляються
**з іменем** («Паста з песто — кедрові горіхи (Арсен)»); техніка на кухні
теж фільтрує. Кошик: складники мінус комора, напій кожному, корм улюбленцю.
Під кошиком — шість джерел одним рядком кожне: Сімейна група · Алергії ·
Трекери · Ваги смаку · Комора · Знижки.

У чаті спершу зʼявляється картка **«Хто вечеряє»** з підтвердженням — «Все
правильно →» збирає вечерю без повторного читання родини, «Змінити» пише в
профіль.

### «Топати чи замовити» — Турбота

`silpo_estimate_delivery⁺(latitude, longitude, cart_total_uah)`: відстань до
455 філій рахуємо самі (гаверсинус із `list_branches`), ціни, пороги й слоти —
з `get_available_delivery_types` + `get_time_slots`. Один виклик замість
1 + N. Відповідь: «самовивіз за 0,79 км — безкоштовно, пішки 9 хв · доставка
додому 99 ₴, мінімум 799 ₴ · добери 820 ₴ — і доставка коштуватиме 69 ₴».
Сума береться з пака на екрані.

### «Перевір усе перед оформленням» — Пораховано до кошика

`precheck_pack(pack_id)` зводить чотири перевірки в одну картку — ті самі
виклики, які асистент має й не читає перед оплатою:

| Рядок | Що перевіряє | Tools |
|---|---|---|
| Топати чи замовити | самовивіз чи доставка під суму пака | `list_branches · get_time_slots · estimate_delivery⁺` |
| Вага кошика | `totalWeight` кошика проти `maxWeight` слоту (додому 40 кг) | `get_shopping_cart_by_id · get_time_slots` |
| Купон | чи ляже на кошик — `canBeAppliedToOrder` (MCP 1.110.0); «лише з доставкою» з `limitText` | `get_my_coupons · get_coupon_details` |
| Промо | ті з персональних, що лягають на кошик, у межах `maxSelect` | `get_my_promos · select_promos⁺` |

Знахідка на живому акаунті: купон «на онлайн чек −10 %» раніше губився зовсім
— він не про товар, а про все замовлення. Тепер він ловиться окремо, і
картка каже: **ляже, але лише з доставкою, не самовивозом**.

### «Куди йдуть гроші» — Прогрес · портрет

`spend_report(window_days=180, top_items=5)`: усі позиції за пів року,
розкладені по розділах, і **що саме** в кожному («Солодощі 1 381 ₴ = три
Парі-Брести, два рулети з маком»). Розділ визначаємо за назвою — `categoryId`
у чеку немає, і це названо чесно. На телефоні — смужки з тапом по розділу; у
профілі — KPI «14 розділів · куди йдуть гроші →».

### Грибниця — Прогрес · рівень

Досвід — **округлені суми чеків**, тож накрутити його не можна: `game.py`
читає їх із `get_my_offline_orders`. Крива геометрична: перший рівень 100 ₴,
кожен наступний на 16 % дорожчий (30-й — 45 633 ₴); 32 чеки — це 18–19 рівень.

На сторінці **Грибниця**: Машрум на землі, від ніжки вниз іде **корінь** —
вузол за вузлом, рівень за рівнем; пройдені заповнені, поточний світиться,
попереду — з ціною; кожні 5 рівнів — нагорода (тап по вузлу забирає), спори —
досягнення. Плитки: Досягнення (з тих самих чеків: «Мандрівник» — різні
`filId`, «Всеїдний» — різні розділи), Скіни (кожні 10 рівнів; два — лише за
досягнення), Магазини (дизайнерські «Сільпо», справжні з пресрелізів),
Нагороди.

Tools: `silpo_get_game_profile⁺`, `silpo_get_achievements⁺`, `silpo_get_skins⁺`
/ `silpo_set_skin⁺`, `silpo_claim_level_reward⁺`, `silpo_get_themed_branches⁺`,
`level_table(upto)`.

- Перше досягнення зі скіном — **«Обійти дизайнерські «Сільпо»»**. Магазини й
  теми справжні, з пресрелізів мережі: S.T.A.L.K.E.R. біля «Комфорт Тауна»,
  тихоокеанська тики на Закревського, кіберкультура з NAVI у Львові. У мережі
  таких **понад 60**, ми зіставили девʼять руками — бо прив'язки «філія →
  концепція» в API немає взагалі.

У застосунку «Сільпо» гейміфікація частково вже є — `/v1/gamification/balance`,
`/v1/achievements/`, колесо фортуни, «Ковбаса фортуни». Але це разові кампанії
(`summer_promo_2026`), а не наскрізний прогрес, і жодного з цих ендпоінтів у
40 tools MCP немає.

### Інші сценарії в панелі

«Що в мене закінчилось» (цикл у днях із дат чеків), «Що зникло з холодильника»
(комора × звички), «Після тренування», «Тижневий закуп сам», «Вгадай мій
настрій», «Спадкова кухня» (рецепт бабусі → кошик), «Чи влізе кошик», аналітика
«Чек-детектив», «Скільки я зекономив», «Чи вигідний Плюхс», «Чи варто це
брати». Ланцюги — у `flows.py` і в UI під «що всередині».

## Методи рівня сценарію (наш MCP-сервер)

аргументами; всередині вони ходять в офіційні tools, і кожен такий виклик видно

## Дрібнички поза кадром

- **Геолокація** — при замовленні й для оцінки доставки (`estimate_delivery⁺`,
  у демо — адреса гостя на Оболоні, 0,8 км до «Сільпо»).
- **Голос агента** — Respeecher `ua-rt`, браузерний голос як запасний; текст
  відповіді показується разом із готовим звуком.
- **Комора** — що вже є вдома, з термінами; прострочене помічається.
- **Кейтеринг і бізнес-компанії** — та сама механіка компанії масштабується:
  бізнес-слот на 500 кг у `get_time_slots` уже є. Але такого немає навіть у
  застосунку вручну — це запит до «Сільпо», не наша реалізація.
- **Спадкова кухня** — рецепт бабусі → кошик із реальних товарів
  (`add_family_recipe⁺`, `find_products_batch`).

## Інтерфейс і запис демо

Три вкладки в телефоні: **Чат** (сценарії, паки, картки), **Кошик**
(справжній кошик акаунта, «згорають сьогодні»), **Профіль** (алергії,
вподобання й ваги, сімʼя, компанії, що є удома, трекери, куди йдуть гроші,
«Департамент дивинок», останні чеки, бейдж рівня → Грибниця).

Панелі поза телефоном: ліворуч — картки сценаріїв із ланцюгом «що всередині»,
праворуч — «Що відбувається»: кожен виклик MCP зі стрілками між ними,
мілісекундами і відповіддю за кліком.

**Режим запису** — `/?rec` (лише телефон) або `/?rec=trace` (телефон +
стрічка); Alt+R / Alt+T. Цифри — кроки демо без миші й набору в кадрі: фраза
набирається в полі сама, кнопки в картках натискаються за текстом:

| Клавіша | Крок |
|---|---|
| `1` | «Збери вечерю, щоб усім підійшло» → «Хто вечеряє» · ще раз — «Все правильно» |
| `2` | «Збираємось компанією на пікнік» → пропозиція · ще раз — «Створити» → QR · ще раз — закупка |
| `3` | «Дійти до Сільпо чи замовити доставку?» |
| `4` | «Куди в мене йдуть гроші?» |
| `5` | у кошик → «Перевір усе перед оформленням» |
| `6` / `7` | що закінчилось / що зникло з холодильника |
| `8` / `9` | компанія в профілі / профіль |
| `0` | чистий дубль (компанії стираються) |

Alt+K — шпаргалка на екрані. Список — `REC_KEYS` у `web/index.html`.

## Архітектура

```
Qwen (Ollama)
   ↓ MCP
web/  ← Starlette як MCP-хост, власної бізнес-логіки не має
   ↓ MCP (stdio)
silpo_agent_mcp/  ← 59 методів рівня сценарію + 43 запропоновані tools
profile_mcp/      ← те, чого немає в акаунті «Сільпо»: алергії, факти, нагороди
   ↓ MCP (streamable HTTP + OAuth)
mcp.silpo.ua  ← офіційні 40 tools
```

Навіщо шар `silpo_agent_mcp`: сирі 40 tools вимагають `branchId`, `companyId`,
`timeslot` і довгих ланцюжків викликів — 3B-модель на цьому ламається. Тут вона
дістає інструменти з одним-двома зрозумілими аргументами, а всі справжні
`silpo_*` виклики видно у трейсі (панель «MCP-стрічка» в UI, tool `mcp_trace`).

59 методів рівня сценарію **не потребують від «Сільпо» нічого нового** — вони
працюють на тих 40 tools, що вже є. Ще 43 позначені як `proposed` (⁺): це те,
чого в MCP немає — родина зі смаками, ваги смаку, трекери й комора, компанія,
доставка одним викликом, рецепти, грибниця — з робочою реалізацією в нас і
чесною позначкою в трейсі.

## Запуск

Потрібен **Python 3.10+**.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m silpo_agent_mcp.login          # OAuth у браузері, один раз
python -m uvicorn web.server:app --port 8000
```

Токени лягають у `.mcp/silpo_tokens.json` і далі оновлюються самі через
`refresh_token`. Claude Desktop і `mcp-remote` **не потрібні**.

Екрани: **асистент** у рамці телефона (Чат · Кошик · Профіль), ліворуч —
картки сценаріїв із ланцюгом «що всередині», праворуч — стрічка «Що
відбувається» з кожним викликом MCP; **профіль**, **грибниця**, сторінка
гостя компанії `/join` і **під капотом** (`/tech`) — для команди: усі
сценарії з ланцюгами, кожен виклик з input і output, редактор демо-даних.

Чат вимагає локальної моделі:

```bash
ollama pull qwen2.5:3b     # 7b помітно надійніша в tool-calling
```

Без Ollama працює все, крім вільного тексту: паки з чека, поповнення звичного,
набори «Сільпо», оптимізація та кошик — це кнопки, не модель.

## Корисні команди

```bash
python -m silpo_agent_mcp.probe probe_out   # схеми 40 tools + зразки (тільки читання)
python -m silpo_agent_mcp.server            # фасад як окремий stdio MCP-сервер
```

`probe` нічого не змінює: жоден write-tool не викликається.

## Перевірка

```bash
.venv/bin/python qa/smoke.py                 # перевірки бекенду на живому API
node --experimental-websocket qa/family.mjs  # «Вечеря на всю сімʼю» → перевірка перед «Оформити», 22 кроки в Chromium
```

Для `family.mjs` потрібен Chromium із `--remote-debugging-port=9222` і сервер
на `:8000`. Перед дублем демо: `POST /api/demo/reset` і `POST /api/weights/rebuild`
(тестові кліки «У кошик» надувають ваги). Режим запису — `/?rec`, клавіші-кроки
описані вище в «Інтерфейс і запис демо».

## Чесні межі — що MCP «Сільпо» не віддає

- **Складу товару** MCP не віддає (`attributes` — країна, ТМ, продавець, БЖУ),
  тому алергени ловляться за назвою.
- **Активацію промо** `get_my_promos` не дає — `select_promos⁺` записує вибір
  у нас, натиснути «+» треба в застосунку.
- **Оформлення** агент не робить і не має робити — доводить до кнопки й
  зупиняється.
- **Трекери** — демо-дані за перемикачем; **компанії** й **ваги** живуть у
  локальному сховищі `.mcp/`; **розділи витрат** визначені за назвою товару.
- Живі числа дрейфують: вікно «пів року» ковзає, купони згорають, рівень росте
  — у день показу цифри в застосунку будуть свої, і це правильно.

## Локальна модель (необовʼязково)

Усі демо йдуть «Напряму» — без моделі. Режим «Через модель» дає той самий
результат тим самим викликом, а модель лише переказує його людською мовою.
Якщо хочеться:

1. Постав [Ollama](https://ollama.com/download); перевір `ollama --version`.
2. Модель під відеопамʼять: 12 ГБ+ — `qwen2.5:14b`, 8 ГБ — `qwen2.5:7b`
   (рекомендовано), 4 ГБ або без відеокарти — `qwen2.5:3b` (працює, але часто
   плутає інструменти).
3. `ollama pull qwen2.5:7b`, Ollama має бути запущена; сервер сам бачить її на
   `http://localhost:11434` (`OLLAMA_URL`, щоб змінити).
4. Windows: `python -m venv .venv`, `.venv\Scripts\Activate.ps1`,
   `pip install -r requirements.txt`, далі як у «Запуск».

Голос агента: Respeecher `ua-rt` (ключ — на сторінці `/tech`), запасний —
голос браузера.
