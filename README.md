# Сільпо Pack Agent 🧾

Агент, який збирає **паки** — іменовані набори справжніх товарів «Сільпо» — з
твоїх реальних чеків, купонів і акцій, а тоді кладе їх у **справжній кошик**
твого акаунта. Проєкт для хакатону **«Сільпо» AI Factory**.

Все, що бачиш нижче, працює на офіційному MCP `https://mcp.silpo.ua/mcp`.
Моків у репозиторії немає.

## Що агент реально робить

| Дія | Реальні tools «Сільпо» під капотом |
|---|---|
| Розпізнає гостя за чеками, а не за анкетою | `get_my_profile`, `get_my_family`, `get_my_food_restrictions`, `get_my_offline_orders`, `get_loyalty_info` |
| Збирає пак під подію | `find_products_batch` |
| Відтворює пак із чека, підмінюючи те, чого немає | `get_my_offline_orders`, `get_similar_products` |
| Поповнює звичне за циклом покупок | `get_my_offline_orders` + власний розрахунок циклу |
| Бере готовий набір «Сільпо» й лишає тільки акційне | `get_product_sets`, `get_products` |
| Показує, які купони й промо спрацюють саме на цей пак | `get_my_coupons`, `get_my_promos`, `get_loyalty_info` |
| Знаходить, де вигідно взяти дві штуки замість однієї | `specialPrices` у результатах пошуку |
| Міняє позицію на дешевшу або акційну | `get_similar_products` |
| Зберігає пак і дублює його в «Обране» акаунта | `add_or_update_favorite_products` |
| **Кладе пак у справжній кошик** і доводить до оплати | `get_my_shopping_cart`, `create_shopping_cart`, `add_or_update_cart_products`, `get_shopping_cart_by_id` |
| Питає «щось знайоме чи щось нове» — і підбирає по-різному | ваги смаку з чеків і свайпів + `find_products_batch` |
| Каже, скільки купонів згоріло невикористаними | `get_my_coupons`, `get_coupon_details`, `rewards[].promoId` у чеках |
| Показує, куди насправді йдуть гроші й що зросло | `get_my_offline_orders` + розкладка по 28 розділах |
| **Відмовляє** купувати, коли зараз дорожче за твою середню | чеки + `find_products_batch` |
| Рахує «Плюхс» на твоїх чеках, а не на банері | `get_my_premium_subscription` + чеки |
| Збирає тиждень сам: комора + цикли + акції | `pantry_missing`⁺, чеки, `find_products_batch` |
| Масштабує «шашлик на шістьох» у кількості | `find_products_batch`, `get_product_sets` |
| Відправляє продукти рідним в інше місто | `find_nova_poshta_settlements`, `find_nova_poshta_offices` |
| Порівнює ціни між магазинами | `find_products_batch` з іншим `branchId` |
| Вирощує **грибницю**: рівні, скіни, досягнення з сум чеків | `get_my_offline_orders` |
| Правиться словами далі в чаті: «прибери пакет», «додай молоко» | `find_products_batch`, `get_similar_products` |
| Кладе подарунковий сертифікат у кошик | `get_my_certificates`, `add_or_update_certificates` |
| Озвучує відповіді вголос українською | Respeecher Space API (`ua-rt`), браузер — запасний |

Оформлення замовлення агент **не виконує** — доводить до кнопки «Оформити»
й зупиняється. Підтверджує людина.

## Грибниця

Досвід — це **округлені суми твоїх чеків**, тож накрутити його не можна.
Крива рівнів геометрична, як у Minecraft: перший рівень коштує 100 досвіду,
кожен наступний на 16% дорожчий. Через це 20-й рівень — це не вдвічі більше за
10-й, а вшестеро.

- **Скіни** Машрума — кожні 10 рівнів; два скіни витратами не купуються взагалі,
  лише за досягнення.
- **Досягнення** рахуються з тих самих чеків: «Мандрівник» — це різні `filId`,
  «Всеїдний» — різні розділи каталогу серед куплених позицій. На реальному
  акаунті одразу закрилось 8 із 14.
- **Грибниця** — картинка з тих самих чисел: вузол на рівень, гілка на полицю,
  яку ти любиш, спора на досягнення. Однакова історія покупок дає однакову
  грибницю — її можна впізнати.
- **Шлях рівнів** — як у Duolingo: вузли стежкою, відступ кожного пропорційний
  ціні рівня, тож геометричну криву видно, а не написано. Нагорода забирається
  натисканням на сам рівень.
- Перше досягнення зі скіном — **«Обійти дизайнерські «Сільпо»»**. Магазини й
  теми справжні, з пресрелізів мережі: S.T.A.L.K.E.R. біля «Комфорт Тауна»,
  тихоокеанська тики на Закревського, кіберкультура з NAVI у Львові. У мережі
  таких **понад 60**, ми зіставили девʼять руками — бо прив'язки «філія →
  концепція» в API немає взагалі.

У застосунку «Сільпо» гейміфікація частково вже є — `/v1/gamification/balance`,
`/v1/achievements/`, колесо фортуни, «Ковбаса фортуни». Але це разові кампанії
(`summer_promo_2026`), а не наскрізний прогрес, і жодного з цих ендпоінтів у
40 tools MCP немає.

## Архітектура

```
Qwen (Ollama)
   ↓ MCP
web/  ← Starlette як MCP-хост, власної бізнес-логіки не має
   ↓ MCP (stdio)
silpo_agent_mcp/  ← 85 tools рівня сценарію
profile_mcp/      ← те, чого немає в акаунті «Сільпо»: алергії, факти, нагороди
   ↓ MCP (streamable HTTP + OAuth)
mcp.silpo.ua  ← офіційні 40 tools
```

Навіщо шар `silpo_agent_mcp`: сирі 40 tools вимагають `branchId`, `companyId`,
`timeslot` і довгих ланцюжків викликів — 3B-модель на цьому ламається. Тут вона
дістає інструменти з одним-двома зрозумілими аргументами, а всі справжні
`silpo_*` виклики видно у трейсі (панель «MCP-стрічка» в UI, tool `mcp_trace`).

Із 85 наших tools **55 не потребують від «Сільпо» нічого нового** — вони
працюють на тих 40, що вже є. Решта 30 позначені як `proposed`: це те, чого в
MCP немає, з робочою реалізацією в нас і чесною позначкою в трейсі.

## Запуск

Потрібен **Python 3.10+**.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m silpo_agent_mcp.login          # OAuth у браузері, один раз
python -m uvicorn web.server:app --port 8000
```

Токени лягають у `.mcp/silpo_tokens.json` і далі оновлюються самі через
`refresh_token`. Claude Desktop і `mcp-remote` **не потрібні**.

Чотири екрани: **асистент** (сценарії — у висувній панелі, кошик — у другій),
**профіль**, **грибниця** і **під капотом**. Останній — для команди: там усі
29 сценаріїв із ланцюгами всередині, кожен виклик MCP з input і output, і
редактор усіх демо-даних просто в браузері.

Чат вимагає локальної моделі:

```bash
ollama pull qwen2.5:3b     # 7b помітно надійніша в tool-calling
```

Без Ollama працює все, крім вільного тексту: паки з чека, поповнення звичного,
набори «Сільпо», оптимізація та кошик — це кнопки, не модель.

## Корисні команди

```bash
python -m silpo_agent_mcp.probe probe_out   # схеми 40 tools + зразки (тільки читання)
python -m silpo_agent_mcp.server            # фасад як окремий stdio MCP-сервер
```

`probe` нічого не змінює: жоден write-tool не викликається.

## Перевірка

```bash
.venv/bin/python qa/smoke.py                 # 26 сценаріїв на живому API
node --experimental-websocket qa/ui.mjs      # 18 перевірок UI у Chromium
```

Покроковий чеклист із числами, з якими можна звірятись, —
[`docs/CHECKLIST.md`](docs/CHECKLIST.md).

## Що MCP «Сільпо» не віддає

- **Склад товару.** `get_product_details.attributes` містить країну, ТМ,
  продавця та БЖУ — інгредієнтів немає. Тому алергени ми ловимо за назвою
  («Вафлі Milka Nussini **з фундуком**»), і це чесно позначено в коді.
- **Активацію персональних промо.** `get_my_promos` лише читає, тож агент
  радить, які 1–5 із 10 обрати, а активує людина в застосунку.
- **Оформлення замовлення.** Такого tool немає — і це правильно.

## Структура

```
silpo_agent_mcp/
  auth.py     OAuth 2.1 + PKCE, локальний callback, сховище токенів
  login.py    одноразовий вхід
  silpo.py    клієнт mcp.silpo.ua: сеанс у виділеній задачі + трейс
  context.py  контекст кошика — ключ до 22 з 40 tools
  facade.py   операції рівня продукту
  packs.py    сховище паків
  insights.py аналітика на наявних tools: купони, витрати, «Плюхс», Нова пошта
  game.py     грибниця: досвід із чеків, рівні, скіни, досягнення
  weights.py  ваги смаку: свайпи й покупки рухають товар і цілу полицю
  flows.py    реєстр end-to-end сценаріїв: назва, фраза, ланцюг усередині
  voice.py    голос: Respeecher ua-rt + підготовка тексту до вимови
  demo.py     усі демо-дані в одному місці — і редаговані з інтерфейсу
  server.py   MCP-сервер: те, що бачить модель
  probe.py    розвідка схем і форматів
profile_mcp/  профіль, памʼять фактів, тригери, нагороди
web/          MCP-хост (Starlette), tool-loop на Qwen, UI
```
