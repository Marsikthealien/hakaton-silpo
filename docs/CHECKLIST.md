# Перевірка Pack Agent

Документ для того, щоб пройтись руками по **всьому**, що вміє агент, і по кожному
пункту переконатись, що результат видно **не тільки в нашому UI, а й у самому
«Сільпо»** — у застосунку, на silpo.ua або у фіскальному чеку.

Зріз реального акаунта, на який спираються числа нижче: **7 вересня 2026**.

---

## 0. Позначки

| Знак | Що означає |
|---|---|
| 🟢 | працює на офіційних 40 tools `mcp.silpo.ua`. Нічого нового від «Сільпо» не треба |
| 🟣 | `proposed` — tool, якого в MCP немає. Реалізований у нас, у трейсі позначений іншим кольором |
| 🟡 | **демо-дані**. Числа наші, не з «Сільпо». Перелік усіх таких місць — розділ 11 |
| 🔗 | є що звірити в самому «Сільпо» |

Правило, за яким усе будувалось: якщо число не виводиться з відповіді API — ми його
не показуємо, а називаємо, чого бракує. Кожен 🟣-tool у відповіді несе поле `spec`
з поясненням, чому він потрібен.

## 1. Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m silpo_agent_mcp.login            # OAuth у браузері, один раз
python -m uvicorn web.server:app --port 8000
```

Відкрити `http://localhost:8000`. Чотири екрани: **асистент** (він же головний),
**профіль**, **грибниця** і **під капотом**.

Навігація влаштована як у застосунку «Сільпо», а не як панель керування:
у хедері лише назва й перемикач вигляду, а між екранами водять іконки всередині
самого застосунку. Сценарії й кошик — **бічні колонки**, які розсовують робочу
область, а не накладаються на неї; коли вони закриті, застосунок займає всю
ширину. У мобільному вигляді кожен екран — телефон із нижньою навігацією.

Іконок-емоджі в інтерфейсі немає: усе намальовано одним лінійним набором SVG
(`ICONS` у `web/app.js`), бо емоджі в кожній системі свої.

Необовʼязково — локальна модель для вільного тексту:

```bash
ollama pull qwen2.5:7b        # 3b теж працює, але помітно гірше в tool-calling
```

**Без Ollama працює все, крім вільної розмови.** Поле вводу не вимикається:
намір розбирається за ключовими словами (розділ 7).

### Перше, що треба побачити

Технічні лічильники навмисно не займають хедер — вони за кнопкою `‹›` у правому
верхньому куті. Натисни її:

| Показник | Норма | Якщо ні |
|---|---|---|
| MCP-tools | **100** | сервер не підняв MCP-хост — дивись лог uvicorn |
| викликів «Сільпо» | росте з кожним сценарієм | токен протух → `python -m silpo_agent_mcp.login` |
| модель | `офлайн` або назва моделі | норма в обох станах |
| MCP-серверів | 2: `silpo-agent` + `profile` | інакше щось не піднялось |

### Клієнт: 41 перевірка у справжньому браузері

Потрібен Chromium і Node 20+. Ганяє реальний UI через DevTools Protocol:
натискає кнопки, чекає на відповідь, читає DOM.

```bash
# 1) браузер із відкритим портом налагодження
chromium --headless=new --no-sandbox --remote-debugging-port=9222 about:blank &

# 2) сервер на 8011 (порт зашитий у qa/ui.mjs)

# 3) прогін
node --experimental-websocket qa/ui.mjs
```

Перевіряє, зокрема: чи відкриваються висувні панелі, чи ставиться питання про
новизну і чи доїжджає відповідь до бекенду, чи всі пʼять іконок профілю
розкриваються в модалки, чи видно криву рівнів як відступ вузла на шляху, чи
показує виклик MCP і input, і output, і чи справді змінює поведінку правка
демо-даних (міняє ціну «Плюхс» на 299 ₴ і повертає назад).

## 3. Екран «Асистент» — сценарії

На екрані сам застосунок і більше нічого. Сценарії — за лівою іконкою в шапці
застосунку, кошик — за правою. Панель розсовує сітку, застосунок звужується;
`Esc` закриває. На вузькому екрані та в мобільному вигляді панель стає накладкою
із затемненням — колонки там просто немає куди подіти.

Усередині лівої панелі — три згортайки з 17 сценаріями й окремий список
«Гроші та звички» з 10 картками аналітики. Кожна картка показує **фразу**, яку
сказала б людина, і **чипи справжніх tools**, що підсвічуються в міру виконання;
ланцюг видно наживо під карткою — з мілісекундами.

**Перевір, що це не хардкод:** назви, фрази й ланцюги приходять із бекенду
(`silpo_agent_mcp/flows.py`, ендпоінт `/api/flows`) — той самий реєстр малює
«Під капотом». Відкрий `curl localhost:8000/api/flows` і звір із карткою.

Перемикач у панелі: **Напряму** або **Через модель**. В обох режимах сценарій
виконується **тим самим MCP-викликом** — тому пак виходить рівно однаковий.
Різниця лише в тому, хто формулює підсумок: у першому це детермінований рядок,
у другому — модель переказує готовий результат людською мовою.

| Перевірити | Як має бути |
|---|---|
| «Через модель» без Ollama | пак усе одно збирається, а замість підсумку — **червона** помилка «ШІ недоступний» |
| «Через модель» з Ollama | той самий пак + жива фраза від моделі, яка ще й озвучується |
| Вердикт-екран (вага, ризик) | модель **не** викликається: там немає ні сум, ні позицій, і вона їх вигадувала б |

Бульбашка «…» обіцяє, що ШІ викликано. Якщо не справдилось — агент каже це
прямо, а не підсовує шаблон замість моделі.

**Пак живе в стрічці чату**, під відповіддю агента — так само, як його зібрала
б розмова. Історія не стирається: попередній пак згортається в рядок
«↑ Як 2026-09-06 · 143.94 ₴ — замінено новим набором», і завжди видно, що з
чого вийшло. Кнопка сценарію теж лишає слід: її фраза й ланцюг tools стають
повідомленнями.

Вкладок у застосунку дві — **Чат** (у ньому ж паки) і **Кошик** «Сільпо».
Нижня навігація однакова на всіх екранах.

### Озвучення відповідей 🟢 + 🟡

Кнопка динаміка в шапці чату. Вголос ідуть **лише відповіді агента** — власні
репліки гість щойно набрав, а «→ pack_remove» слухати нема сенсу.

**Два шляхи, перемикаються самі:**

| | Respeecher Space API 🟢 | Браузер 🟡 |
|---|---|---|
| Голос | справжній український, модель `ua-rt` | системний; українського часто **немає** |
| Наголоси | так: «йог+урт» → наголос на «у» | ні |
| Потребує | ключ (безкоштовний) | нічого |
| Коли працює | якщо ключ є | завжди, як запасний |

Ключ: `space.respeecher.com/api-keys` → «Під капотом» → **Голос агента** →
вставити. Лягає в `.mcp/respeecher.json`, тека в git не потрапляє. Або змінна
`RESPEECHER_API_KEY`.

Промокод із каналу хакатону — `SILPO_50`, $50 кредитів, **дійсний до кінця
14 вересня 2026**; невикористане згорає.

| Перевірити | Як має бути |
|---|---|
| «Під капотом» → Голос агента | без ключа — «немає, озвучує браузер»; з ключем — перелік голосів |
| «Перевірити голос» | синтезує фразу й програє її |
| Натиснути динамік у чаті | скаже «Готовий. Питайте», тост назве джерело голосу |
| Спитати щось | відповідь озвучиться; нова перебиває попередню |
| Ключ протух / ліміт | **не мовчить**: відкочується на браузер і показує це в підказці кнопки |
| Перезавантажити сторінку | стан памʼятається (`localStorage`) |

**Текст для вимови готується окремо** (`silpo_agent_mcp/voice.py` → `for_speech`),
за порадою Respeecher із каналу хакатону:

- числа, час і дати словами: «шосте вересня», а не «2026-09-06»;
- гроші цілими гривнями: «сто сорок чотири гривні», а не «сто сорок три кома
  дев'яносто чотири» — копійки в розмові не вимовляють;
- посилання, шляхи, `uuid`, id паків та імена tools **не читаються взагалі**;
- «·» стає крапкою, інакше речення злипаються в одне дихання;
- апостроф усередині слова лишається — без нього «п'ять» розпадається на «п ять».

**Той самий гайд лежить і в системному промпті** (`web/chat.py` → `VOICE_STYLE`):
тільки українською, звичайним текстом без списків, максимум два пункти в реченні,
коротка фраза очікування **перед** викликом tool («Секунду.», «Дай перевірю.»),
і перечитати відповідь перед відправкою. Це не косметика: те, що добре
читається очима, у голосі розсипається.

**Межа чесно**: морфологія числівників спрощена. «Спрацював 1 купон» вимовиться
як «один купонів» — рід і відмінок ми не узгоджуємо. Виправляється текстом
самої відповіді, не синтезом.

### Редагування пака словами 🟢

Щойно пак зібрано, підказки під полем вводу міняються на правочні. Пиши далі
в тому ж чаті — `pack_id` називати не треба, береться останній пак:

| Фраза | Що робить | Tool |
|---|---|---|
| «прибери пакет» | прибирає позицію за фрагментом назви | `pack_remove` |
| «додай молоко» | шукає в «Сільпо» з урахуванням алергій і ваг смаку | `pack_add` |
| «зроби три пляшки води» | змінює кількість | `pack_set_qty` |
| «заміни чипси на дешевше» | шукає альтернативу | `pack_swap_named` |
| «заміни чипси на акційне» | те саме, але серед знижок | `pack_swap_named(prefer='promo')` |

Позиція шукається **за фрагментом назви**, як людина очима в списку: «чипси» →
«Чипси Люкс зі смаком краба». Якщо збігу немає, агент перелічує, що є в паку.

**Працює і без моделі**: роутер намірів витягує предмет правки з фрази й
відкидає службові слова («прибери звідти пакет, будь ласка» → `пакет`).
«додай воду і хліб» бере тільки до сполучника — інакше з двох товарів вийшов би
один безглуздий запит.

#### Що в мене закінчилось 🟢

- **Очікувати**: пак із того, що береться регулярно і чий цикл минув. Кожна позиція має цикл: «вода — кожні 15 днів, минуло 55».
- **Звірка**: цикл рахується з дат у чеках. Візьми будь-яку позицію з пака, знайди її в «Останніх чеках» на Профілі й перевір дати руками.
- Сьогодні на цьому акаунті: **17 звичок розпізнано, 8 із них «пора»**. Портрет показує перші 8 і перші 5 — це обмеження показу, не розрахунку; повний перелік дає «Не забудь».

#### Що зникло з холодильника 🟣🟡

- Комора — наше сховище (`silpo_pantry_sync`). Порожню комору агент зіставляє зі звичками з **реальних** чеків.
- Це і є сенс сценарію: «Сільпо» не знає, що в тебе на полиці, а трекер не знає про твою алергію. Зшиває агент.

#### Після тренування 🟣🟡

- Дані самопочуття вводяться вручну або приходять із «конектора» (Профіль → Джерела даних). Самі конектори — демо.
- Підбір під стан — уже справжній `find_products_batch`.

#### Розумний бюджет 🟢

- Введи «лишилось 840 ₴ на 7 днів».
- **Очікувати**: кошик рівно під залишок і, головне, **перелік того, що не влізло, з причиною по кожному**: «не влазить у бюджет (найдешевше 23.2 грн)», «пропущено через «мак»».
- Порядок: спершу те, що вже мало б закінчитись, потім те, що береш найчастіше.

- **🔗 Звірка**: застосунок → Сімейний доступ. Побач, що там **немає жодного поля про смаки** — лише спільні бонуси. У кота Мурчика є кнопка «Вказати вік», і на цьому все.

#### Спадкова кухня 🟣🟡 — сімейна книга рецептів, повністю наше сховище. Складники → реальні товари.

### 3.3 Магазин і логістика

#### Топати чи замовити 🟢 + 🟣

- Дай геолокацію або введи адресу словами.
- **Очікувати**: таблиця «пішки N хв і 0 ₴» проти «доставка X ₴ через Y год», і рядок «добери ще N ₴ — і доставка коштуватиме 1 ₴ замість 99».
- Відстань рахується гаверсинусом із реальних `latitude`/`longitude` **455 філій**. Жодних зовнішніх геосервісів.
- **🔗 Звірка**: пороги доставки (`deliveryCostMap`) — реальні. Порівняй із чекаутом на silpo.ua для того самого магазину.

#### Чи влізе кошик 🟢

- **Очікувати**: вага кошика поруч із лімітом кожного способу отримання.
- Поле `maxWeight` лежить у кожному слоті доставки й **не використовується ніде**: доставка додому 40 кг, для бізнесу 500 кг, самовивіз без ліміту.
- Попередження **до** оформлення, а не дзвінок кур'єра після.

#### Маршрут по залу 🟣

- Потрібен зібраний пак. Розділи — **28 справжніх** із `get_categories_tree`, у порядку самого «Сільпо».
- Порядок можна переставити один раз — запамʼятається під конкретний `branchId`.
- **Чесне обмеження**: прив'язку товару до розділу доводиться **вгадувати за назвою** — `categoryId` немає в картці товару навіть тоді, коли товар дістали запитом ПО КАТЕГОРІЇ. Класифікатор доведено до 112 назв зі 112 на цьому акаунті, але це наш словник.

#### Відправ батькам у Полтаву 🟢 🔗

- Місто + список + за бажанням номер відділення.
- **Очікувати**: пак + перелік відділень. Для Полтави — **25 відділень**.
- **🔗 Звірка**: `find_nova_poshta_settlements` і `find_nova_poshta_offices` — офіційні tools «Сільпо». Порівняй список із novaposhta.ua.
- **Обмеження**: тип доставки в кошику агент не змінює — tool на це в MCP немає. Обирається на чекауті людиною.

## 4. Панель «Гроші та звички»

Внизу лівої висувної панелі, під сценаріями. Десять карток, які відповідають
**одним числом**. Жодного нового tool — усе на тих 40,
що вже працюють. Не використовує їх ніхто, бо відповідь живе **на стику двох викликів**.

### Чек-детектив 🟢 🔗 — найсильніша картка для пітчу

| | |
|---|---|
| **Очікувати** | «Спрацювало 1 купонів на 3 144.81 ₴. Зараз згорає 11 — це ще 275 балобонусів» |
| **Як це працює** | `coupon.promoId` ↔ `order.rewards[].promoId` — **точний збіг**, не здогадка. На цей звʼязок вказує сама дока MCP |
| **🔗 Звірка** | застосунок → **Купони**. Порахуй руками, скільки їх і коли згорають. Агент має показати ті самі. Далі відкрий будь-який чек, де купон спрацював, — у ньому буде рядок винагороди |
| **Дірка в API** | `get_my_coupons` не віддає `usedCount` — він є лише в `get_coupon_details`, тобто по одному купону за виклик. Історію ми відновлюємо з чеків |

Окремо перевір: **скільки купонів не активовано**. Активувати їх агент не може —
tool на запис немає, тисне людина в застосунку.

### Скільки я зекономив 🟢 🔗

- **Очікувати**: «За 32 чеків: сплачено 8 966.01 ₴, знижок 2 973.64 ₴», частка знижок **24.9%**.
- **🔗 Звірка**: Профіль → Останні чеки → «Оригінал чека». У фіскальному чеку є сума знижки. Звір із тим, що показує агент.
- Це єдина метрика користі, яку **не треба вигадувати**.

### Куди йдуть гроші 🟢

- **Очікувати**: «3 345.88 ₴ за 30 днів проти 2 117.54 ₴ у попередні 30», і розкладка по розділах із дельтою. Сьогодні «Напої» **+367%**.
- Категорії, що зросли на ≥25%, підсвічені.
- **Обмеження**: розділ визначається за назвою (див. «Маршрут по залу»).

### Чи вигідний «Плюхс» 🟢 🔗

- **Очікувати**: «Береш на 3 057 ₴ на місяць. Підписка окупається від 1 990 ₴ — зараз це вигідно».
- 🟢 Факт наявності підписки — з `get_my_premium_subscription`.
- 🟡 **Ціна 199 ₴, кешбек 10%, поріг 500 ₴ — константи в коді** (`insights.py`), узяті зі сторінки silpo.ua/subscription. MCP цих умов не віддає взагалі.
- **🔗 Звірка**: відкрий silpo.ua/subscription і звір умови. Якщо змінились — правити `PLUS_PRICE_UAH` / `PLUS_CASHBACK`.

### Не забудь 🟢

- **Очікувати**: «Прострочено 7, найближчими 5 днями скінчиться ще 1». Відстежується **17 звичок**.
- Цикл із чеків, без жодного нагадування від людини. Плюс окремий рядок про кота, якщо корм є в чеках.
- **Звірка**: «Хліб «Київхліб» — цикл 13 дн., минуло 18». Знайди хліб в «Останніх чеках» і перевір інтервали між датами руками.

### Що беруть у моєму магазині 🟢 🔗 — `get_popular_categories` живої філії. Сьогодні: Фрукти, Сири напівтверді, Морепродукти, Тихі вина. Tool віддає лише перелік без чисел — «наскільки популярні» сказати не можна, і ми цього не вигадуємо.

### Ризик збирання 🟢

- Джерело позицій: пак, інакше **активне онлайн-замовлення в збиранні**, інакше кошик.
- `get_replacements` віддає саме позиції з ризиком збирання — це **не** просто `stock: 0` — і кандидатів на заміну від самого «Сільпо». Tool створений рівно для цього і не використовується ніде.
- **Заміни фільтруються за алергіями й дієтами** з акаунта: інакше «рішення наперед» підсунуло б те, чого людині не можна. Відсіяне видно в `hidden_by_restrictions`.
- Сенс: попередження **до оплати** замість дзвінка кур'єра після.

### Екослід кошика 🟢🟡 — оцінка з `weighted` і `totalWeight`. **Пакування (пластик/скло/папір) у картці товару немає**, тож це оцінка, а не вимір, і так і підписано.

### Чи варто це брати 🟢 — агент, який **відмовляє**

- Введи «чипси».
- **Очікувати**: «⏸ почекай · зараз 66.99 ₴ — на 26% дорожче за твою середню 53.32 ₴».
- **🔗 Звірка**: знайди чипси в «Останніх чеках» і порахуй середню руками.

### Де вигідніше 🟢 🔗

- Список + місто + скільки магазинів.
- **Очікувати**: різниця між філіями. Сьогодні на двох позиціях — **40 ₴**.
- Жодного нового tool: `find_products_batch` приймає `branchId` прямо в аргументах.
- **🔗 Звірка**: відкрий silpo.ua, переключи магазин у шапці й порівняй ціну того самого товару.

## 5. Екран «Грибниця»

Заходити через іконку гриба в шапці застосунку або через значок рівня в портреті профілю.

Головне, що треба зрозуміти: **досвід не можна накрутити**. Це округлені суми
чеків із `get_my_offline_orders`. Не «активність у застосунку», не бали за вхід,
не завдання.

### Що звіряти

| Показник | Сьогодні | Як перевірити |
|---|---|---|
| Досвід | **8 967 ₴** | сума всіх чеків = 8 966.01 ₴. Профіль → Останні чеки |
| Рівень | **19** | на шляху нижче: поріг 19-го — 8 417, 20-го — 9 863 |
| До наступного | **896 ₴** | 9 863 − 8 967 |
| Досягнення | **9 / 14** | плитка «Досягнення» |
| Скіни | **3 / 8** | плитка «Скіни» |
| Чеків враховано | **32** | має збігатися з профілем і з «Скільки я зекономив» |

Число чеків і сума на грибниці, у профілі та в «Скільки я зекономив» мають бути
**однакові**. Якщо десь 10 чеків замість 32 — це баг.

«Досвід» і «витрачено всього» — те саме число, тож воно показується **один раз**.

### Шлях — окрема сторінка `/road`

Заходити з грибниці: іконка карти в шапці або картка «Шлях рівнів».

Стежка вузлів **зверху вниз, від 1-го до 40-го** — як дорога, якою вже пройшов і
яка тягнеться далі. Пройдені рівні зелені, поточний фіолетовий і підписаний
«ти тут», попереду — сірі; рівні з подарунком помічені.

**При першому заході сторінка сама прокручується на поточний рівень**, далі
гортаєш вручну.

**Криву видно, а не написано**: відступ вузла ліворуч росте разом із ціною рівня
(корінь із частки — лінійно різниця між сусідніми рівнями непомітна). Перший
рівень коштує 100 ₴, 19-й — 1 446 ₴, 30-й — 7 401 ₴.

| Дія | Що має статись |
|---|---|
| Натиснути пройдений рівень із подарунком | видає промокод і показує його в модалці |
| Натиснути його ще раз | показує вже виданий код і дату |
| Натиснути недосяжний рівень | каже, скільки ще треба: «ще N ₴ — це M середніх чеків» |
| Натиснути рівень без нагороди | пояснює ціну переходу й що тут відкривається скін |
| Прокрутити вгору | видно перші рівні по 100–200 ₴ — і те, наскільки вони дешевші |

### Картка грибниці — компактна

Рівень, смужка прогресу, досвід і скільки лишилось — і сама грибниця смугою під

`summer_promo_2026` і згорають разом із промо. Наскрізної шкали, яка росте
роками, немає, і **жодного з цих ендпоінтів немає в 40 tools MCP**.

## 6. Екран «Профіль»

Заходити через іконку профілю в шапці застосунку або в нижній навігації.

### Портрет 🟢 🔗

Витрачено, зекономлено, середній чек, улюблений магазин, скільки звичок
розпізнано. Усе з чеків.

### Картка «Грибниця» — рівень, прогрес і скільки лишилось. Веде на грибницю.

### Смаки й обмеження — одна секція, сім іконок

Раніше вподобання, алергії, сімʼя, техніка, звички, ваги та конектори були
сімома окремими картками на різній висоті. Тепер це один блок:
**іконка → модалка**. Модалка може відкрити модалку (сімʼя → учасник) — і тоді
в шапці зʼявляється «назад».

| Іконка | Що всередині | 🔗 Звірка в «Сільпо» |
|---|---|---|
| **Алергії** | список алергенів + дієти з акаунта | застосунок → **Простір вподобань**: девʼять харчових категорій, але **поля для алергії немає ніде** |
| **Вподобання** | люблю / не люблю | змінюється й словами в чаті — агент оновить сам |
| **Моя сімʼя** | склад із «Сільпо» + кнопка «Зібрати вечерю на всіх» | застосунок → **Сімейний доступ**: там Назар і кіт Мурчик, але **жодного поля про смаки** |
| **Техніка** | що є на кухні | наше: у MCP такого немає |
| **Беру регулярно** | 17 звичок із циклом | звір цикл із датами в «Останніх чеках» |
| **Памʼять** | факти, які агент запамʼятав із розмов | наше: `profile` MCP |

**Перевір «Алергії» на межах**: фільтр іде по **основі** слова з обох боків.
Алерген «мак» **не** блокує «Вермішель зі смаком курки» й **не** блокує
«Макарони», але блокує «Рулет з маком». Алерген «сметана» ловить «Чипси зі
смаком **сметани**» — у слів від шести літер відкидається кінцева голосна.
Поріг саме шість: «кава» → «кав» знайшло б «кавун». Видно прямо в паку —
пропущені позиції названі з причиною.

**Перевір «Мою сімʼю» до кінця**: натисни «Зібрати вечерю на всіх». У паку має
зʼявитись рядок «Виключено для всієї родини: арахіс, горіхи» — алергія будь-кого
блокує товар для **всього** кошика, а не для окремої тарілки.

### Департамент дивинок 🟣 🔗 — у тій самій секції

| | |
|---|---|
| **Дія** | «Почати», далі ♥ або ✕ |
| **Очікувати** | після свайпу — рядок «+2 до «…» і до полиці «Солодощі»» |
| **🔗 Звірка вправо** | свайп ♥ пише в **справжнє «Обране»** акаунта. Відкрий застосунок → Обране |
| **Звірка вліво** | свайп ✕ ніде в «Сільпо» не зберігається — **це і є дірка** |
| **Колода** | не випадкова: полиці, які ти любиш, **плюс одна «на виріст»**. Кожна картка підписана, чому вона тут |

### Ваги смаку 🟣 — усередині «Вподобань»

Це той самий смак, лише порахований, а не введений, тож і живе в тій самій
модалці, під полями «Люблю / Не люблю».

- «Перерахувати з чеків» → **32 чеки, 157 позицій**.
- Сьогодні: Напої +39, Солодощі +23.05, Бакалія +22, Фрукти/овочі +19.18.
- Свайп вправо **+2**, уліво **−2** — і товару, **і його полиці**.
- **Перевір зв'язок**: свайпни щось уліво → перерахуй ваги → полиця просяде →
  гілка на грибниці стане тоншою.

### Знайоме чи нове — перевірка в дві дії

1. Панель сценаріїв → «Страва на суму» → **«Щось знайоме»**.
2. Повтори те саме → **«Щось нове»**.

**Очікувати**: різні товари. «Чипси Люкс» (з чеків) проти «Чипси яблучні
«Премія»» (не брав жодного разу).

Чому це окреме питання: «знайоме» і «нове» — **різні осі**. Свайп уліво теж
робить товар знайомим. Якщо знайомого немає в бюджеті — агент бере незнайомий і
**каже про це**.

### Тумблер «Пропонувати відразу з бонусами» 🟢

Найкраща демонстрація одним кліком:

1. Запусти «Повтори останній чек», запамʼятай суму.
2. Увімкни тумблер.
3. Запусти той самий сценарій ще раз.

**Очікувати**: інша сума й підписані заміни. Тумблер діє на **всі** сценарії.

### Останні чеки 🔗

Картки, а не рядки: дата й сума великим, магазин, склад, і **дві справжні
кнопки** — «Повторити як пак» і «Оригінал чека ↗».

**🔗 Головна звірка проєкту**: «Оригінал чека» відкриває фіскальний чек на
`receipt.silpo.elkasa.com.ua`. Звір позиції, суму й знижку з тим, що показує
агент.

Під списком — рядок «Показано 10 із 32»: решта теж враховані в досвіді, звичках
і аналітиці.

## 7. Чат

### З моделлю

Увімкни Ollama, перезавантаж сторінку — плашка «модель» покаже назву.

Спробуй:

| Фраза | Що має статись |
|---|---|
| «повтори минулу покупку» | пак із чека |
| «хочу вечерю на 400 грн» | **спершу питання про новизну**, потім рецепт і продукти |
| «шашлик на шістьох» | пак із кількостями на людей |
| «скільки я зекономив» | число з чеків |
| «мій рівень» | рівень і грибниця |
| «чи варто брати чипси» | «почекай» із поясненням |
| «у мене алергія на фундук» | агент запише в профіль і далі виключатиме |

Модель бачить **курований набір** інструментів, а не всі 95: 3B-модель захлинається
на 40 сирих tools із uuid-аргументами.

### Без моделі — навмисна поведінка, а не поломка

Вимкни Ollama. Поле вводу **не вимикається**. Намір розбирається за ключовими словами,
і агент чесно каже: «Модель офлайн, впізнав «повтори чек»».

Перевір, що роутер не плутається:

| Фраза | Має піти в |
|---|---|
| «нагадай що **скін**чилось» | `reminders`, **не** у грибницю (слово «скінчилось» містить «скін») |
| «які **скін**и відкриті» | грибницю |
| «що в мене закінчилось» | `reorder_pack` |

Сенс: сценарій має доводитись до кінця навіть без GPU. Це вимога демо, а не компроміс.

## 8. Екран «Під капотом»

Екран для команди, не для гостя: іконка ⚙ у хедері. Три речі, яких раніше не було.

### 8.1 Сценарії й що всередині — замість схеми «ланцюг агента»

Усі **29 end-to-end сценаріїв**, згруповані. Розгорни будь-який — і побачиш
покроковий ланцюг: який tool, навіщо, і якого він роду.

| Колір крапки | Що означає | Скільки кроків |
|---|---|---|
| 🟢 зелений | офіційний tool `mcp.silpo.ua` | 55 |
| 🟣 фіолетовий | tool, якого в MCP немає — ми його пропонуємо | 13 |
| 🟡 бурштиновий | наш розрахунок, не виклик API | 13 |

Останній рядок кожного ланцюга — **результат на реальних даних**, а не опис.

**Перевір, що це одне джерело**: назви й фрази тут ті самі, що на картках
сценаріїв. Обидва беруть їх із `/api/flows` (`silpo_agent_mcp/flows.py`).

### 8.2 Виклики MCP — з input і output

Список викликів наживо. **Натисни будь-який** — відкриється картка з:

- **Input** — аргументи, з якими пішов виклик (`branchId`, `deliveryType`, запити);
- **Output** — що повернулось, до 1800 символів, далі обрізано.

Так видно, що дані справжні, а не намальовані. Наприклад, у відповіді
`silpo_get_my_profile` буде реальний `id` акаунта, у `find_products_batch` —
`totalFound` і масив товарів із цінами.

Прапорець «наживо» вимикає автооновлення кожні 2.5 с — щоб виклик не втік,
поки його читаєш.

### 8.3 Демо-дані — редаговані просто в браузері

Чотири набори, кожен із текстовим полем, «Застосувати» і «Скинути»:

| Набір | Що можна змінити | Чому воно наше |
|---|---|---|
| **Дизайнерські «Сільпо»** | перелік магазинів і тем | прив'язки «філія → концепція» в API немає |
| **Нагороди за рівні** | рівень, назва, тип нагороди | `get_promo_codes` уміє лише читати |
| **Умови «Плюхс»** | ціна, кешбек, поріг доставки | MCP каже лише «є підписка чи ні» |
| **Крива рівнів грибниці** | `base`, `growth`, `max_level` | наша механіка |

**Перевір, що це не декорація** (30 секунд):

1. У «Умови «Плюхс»» зміни `price_uah` на `399` → «Застосувати».
2. Панель «Гроші та звички» → «Чи вигідний «Плюхс» → поріг стане **7 980 ₴**,
   вердикт зміниться на «поки ні».
3. Повернись і натисни «Скинути» → поріг знову **1 990 ₴**.

Те саме з кривою рівнів: зміни `growth` на `1.10` — і рівень на грибниці
перерахується на льоту.

Значення за замовчуванням лежать у коді (`silpo_agent_mcp/demo.py`), тож
«Скинути» працює завжди, навіть якщо наредагувати дурниць.

### 8.4 Накопичений стан

Чотири файли, які агент наповнює сам: `proposed.json` (комора, самопочуття,
свайпи, вподобання родини), `weights.json`, `game.json`, `packs.json`.
Видно розмір, є кнопка «видалити» — щоб перевірити сценарій **з нуля**.

### 8.5 Решта екрана

Доступ до «Сільпо» (стан токена, вставити свій, пройти OAuth заново), перелік
того, чого MCP не дозволяє, кнопка «перевірити зараз» для плаваючого збою з
сертифікатами (робить **пʼять** викликів поспіль — один успішний нічого не
доводить) і список зібраних паків.

## 9. Наскрізний прогон — від фрази до кошика

Найважливіший тест. Пройди повністю:

1. **Профіль** → плитка «Алергії» → впиши «горіхи»; увімкни тумблер «з бонусами».
2. **Асистент** → панель «Сценарії» → «Повтори останній чек».
3. Під паком, **усередині картки**, зʼявиться червоний блок алергенів — з назвою товару й словом, на якому спрацювало. Він належить конкретному паку, тож і живе в ньому, а не смугою на всю сторінку.
4. Кнопка **«Знижки»** — купони, мультипаки «візьми 2», скільки бракує до Дольок.
5. У будь-якої позиції: **«Відомості»** (склад, БЖУ, фото, посилання на silpo.ua) і **«Обрати інший →»** (картки з фото й дельтою ціни).
6. **«Гроші та звички» → Ризик збирання** — що можуть не зібрати.
7. **«У кошик «Сільпо»»**.
8. Панель «Кошик» на правому краю → ⟳. Товари, сума, вага, слот, поріг Дольок.
9. **🔗 Відкрий кошик у застосунку «Сільпо» або на silpo.ua.**

**Товари мають бути там.** Це і є доказ, що агент має руки, а не язик.

**Оформлення замовлення агент не виконує** — доводить до кнопки «Оформити» й
зупиняється. Такого tool у MCP немає, і це правильно. Підтверджує людина.

## 13. Відомі обмеження

| Обмеження | Де видно |
|---|---|
| Розділ товару вгадується за назвою | маршрут по залу, «Куди йдуть гроші», ваги смаку |
