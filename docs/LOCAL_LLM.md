# Локальна модель: як запустити проєкт у себе

Інструкція для Windows. Розрахована на те, що ти робиш це вперше — тож усе по кроках,
з поясненнями «навіщо».

## Що взагалі відбувається

Наш агент — це набір інструментів (tools), якими керує мовна модель. Модель працює
**у тебе на компʼютері**, нічого нікуди не надсилається. Її піднімає програма
**Ollama** — вона тримає модель у фоні й відповідає на запити застосунку.

Ланцюг такий:

```
ти пишеш у чат
   ↓
Qwen (локально, через Ollama)
   ↓ MCP
наш сервер silpo-agent            ← 58 інструментів
   ↓ MCP + OAuth
mcp.silpo.ua                      ← офіційні 40 інструментів «Сільпо»
```

**Важливо:** без моделі проєкт теж працює. Усі сценарії ліворуч на головній —
кнопки, вони не потребують Ollama. Модель потрібна лише для **вільного тексту**
(«хочу вечерю на 400 грн» словами). Тож якщо щось не запуститься — демо не зламається.

---

## Крок 1. Постав Ollama

1. Відкрий <https://ollama.com/download> → **Download for Windows** → запусти інсталятор.
2. Після встановлення Ollama сама стартує й висить у треї (значок біля годинника).
3. Перевір, що працює. Відкрий **PowerShell** (Пуск → набери `powershell`) і встав:

```powershell
ollama --version
```

Має вивести версію. Якщо пише «не є внутрішньою командою» — перезавантаж компʼютер,
інсталятор не встиг прописати шлях.

---

## Крок 2. Обери модель під свою відеокарту

Модель має вміститись у памʼять відеокарти, інакше вона поповзе на процесор
і працюватиме дуже повільно.

**Скільки в тебе відеопамʼяті:** натисни `Ctrl+Shift+Esc` → вкладка
**Продуктивність** → **Графічний процесор** → рядок «Виділена памʼять графічного процесора».

| Відеопамʼять | Модель | Команда |
|---|---|---|
| 12 ГБ і більше | **qwen2.5:14b** — найкраща | `ollama pull qwen2.5:14b` |
| 8 ГБ | **qwen2.5:7b** — рекомендую | `ollama pull qwen2.5:7b` |
| 6 ГБ | qwen2.5:7b, але буде тіснувато | `ollama pull qwen2.5:7b` |
| 4 ГБ або немає відеокарти | qwen2.5:3b — працює, але часто плутається | `ollama pull qwen2.5:3b` |

**Чому не 3b.** Модель має обрати правильний інструмент із шістнадцяти й заповнити
його аргументи. Трибільйонна модель на цьому регулярно спотикається: то вигадає
неіснуючий аргумент, то викличе не той інструмент. Сімка помиляється помітно рідше,
і це саме той випадок, коли розмір вирішує.

Завантаження — це кілька гігабайтів, тож на повільному інтернеті займе час.
Перевір, що модель на місці:

```powershell
ollama list
```

## Крок 3. Підніми проєкт

У PowerShell, у теці проєкту:

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

> Якщо `Activate.ps1` не запускається і PowerShell лається на політику виконання —
> виконай один раз:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, підтверди `Y`, і повтори.

Далі — вхід у «Сільпо». Відкриється браузер, увійди своїм акаунтом:

```powershell
python -m silpo_agent_mcp.login
```

Токен збережеться в `.mcp\silpo_tokens.json` і далі оновлюватиметься сам.
У Git він не потрапляє — файл у `.gitignore`.

> Потрібен **власний** акаунт «Сільпо» з історією покупок. Агент читає твої чеки,
> твої купони й кладе товари у **твій справжній кошик**. На чужому акаунті
> нічого не запрацює.

Запуск:

```powershell
python -m uvicorn web.server:app --port 8000
```

Відкрий <http://localhost:8000>.

У шапці праворуч має світитись **модель qwen2.5:7b**. Якщо там «офлайн» — Ollama
не запущена або модель не завантажена.

## Крок 4. Якщо хочеш іншу модель

За замовчуванням застосунок сам обирає найкращу з наявних у такому порядку:
`qwen2.5:7b` → `qwen2.5:3b` → `llama3.2:3b` → перша-ліпша.

Задати вручну — перед запуском:

```powershell
$env:OLLAMA_MODEL = "qwen2.5:14b"
python -m uvicorn web.server:app --port 8000
```

Змінна діє лише в цьому вікні PowerShell. Закрив — треба задавати знову.

Якщо Ollama крутиться не на цій машині (наприклад, на іншому компʼютері в мережі):

```powershell
$env:OLLAMA_URL = "http://192.168.1.50:11434"
```

## Що робити, коли щось не так

**«модель офлайн» у шапці.** Ollama не запущена. Знайди її значок у треї або
виконай `ollama serve` у PowerShell і лиши це вікно відкритим.

**Відповідає дуже повільно.** Модель не влізла у відеопамʼять і рахується на
процесорі. Візьми меншу — `qwen2.5:3b`. Перевірити, куди пішла модель, можна
командою `ollama ps`: у стовпчику `PROCESSOR` має бути `GPU`, а не `CPU`.

**Модель вигадує неіснуючі товари або плутає інструменти.** Це і є та проблема,
через яку раджу 7b. Тимчасово користуйся кнопками сценаріїв — вони ходять у ті самі
інструменти, тільки без моделі.

**Вільний текст працює навіть без Ollama.** Ми зробили простий розбір наміру за
ключовими словами: «повтори минулу покупку» або «вечеря на 400 грн» спрацюють і так.
Агент чесно напише, що модель офлайн і він упізнав сценарій правилами.

**Помилка про токен «Сільпо».** Перезайди: `python -m silpo_agent_mcp.login`.
Стан токена видно на сторінці **Під капотом** — там же можна вставити свіжий вручну.

**Порт 8000 зайнятий.** Запусти на іншому: `--port 8001`.

## Необовʼязково: розпізнавання складу товару

Один сценарій — перевірка алергенів — читає склад із **фотографії етикетки**, яку
віддає MCP «Сільпо». Для цього потрібен Tesseract.

1. Постав звідси: <https://github.com/UB-Mannheim/tesseract/wiki> (файл `.exe`).
2. Під час встановлення обовʼязково познач **Ukrainian** у списку мов.
3. Постав галочку «Add to PATH», інакше програма його не знайде.

Без Tesseract нічого не зламається: агент перейде на визначення алергенів за назвою
товару й чесно позначить, що впевненість низька.

